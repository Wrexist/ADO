# LEARNINGS.md

One line per learning. The nightly analyzer (parked, p5) consumes this file; keep entries terse and factual.

- 2026-07-12: Per-model prompt tuning is cheaply done as a preamble + optional per-model variant over one shared `body` — avoids duplicating every prompt per AI while still shaping output for the selected model.
- 2026-07-12: Specialized "agents" are best modeled as dispatch profiles (system preamble + verifiable loop + exit check), not new runtime types — they compose with existing prompts via a render helper and need no runner changes.
- 2026-07-12: Custom user data (prompts) follows the same secure pattern as secrets — gitignored JSON under data/, token-gated CRUD, built-ins served from the client bundle so the API payload stays small.
- 2026-07-12: The catch-up scheduler must NOT advance a job's last-run on failure, or a failing nightly job silently marks itself done and never retries; only a clean run persists the timestamp.
- 2026-07-12: Sub-minute samplers (sysmon 10s, health 60s) should stay on naked intervals — a missed 10s sample is meaningless, so persisting last-run for them is pure overhead; the scheduler is for catch-up-worthy daily/hourly work.
- 2026-07-12: WAL-safe backup = `VACUUM INTO` (not a file copy) + reopen-and-assert row count before rotation; a silent short-write must fail loudly rather than leave a corrupt "backup".
- 2026-07-12: Vitest path filters are resolved from the repo root (where the config lives), not the `-w` workspace cwd — filter with `apps/server/src/...` from root, not `src/...`.
- 2026-07-12: The dashboard already holds at 53 repos with no layout break because both views cap their lists (View A grid at 6, View B table at 5, each + "View all") — capping list widgets defensively pays off at scale for free.
- 2026-07-12: Pixel-diff visual baselines should wait until after the pixel-polish sign-off (p3.5) or they just get re-baselined by the polish; a render + zero-console-error smoke gate gives regression coverage in the meantime without that churn.
- 2026-07-12: launchd starts with a minimal PATH, so a LaunchAgent must invoke the app via a login shell (`/bin/sh -lc`) to pick up node/nvm — running `node` directly from a plist fails after reboot.
- 2026-07-12: The server has no JS build (runs via tsx), so autostart (pm2/launchd) invokes `npm run start -w @ado/server` rather than a compiled entrypoint.
- 2026-07-12: A stable event id is correct ONLY for create-once/idempotent facts; for anything whose value changes over time (scanner rescans, GitHub PR/CI enrichment) a stable id makes the bus dedup silently drop every update — use a fresh id per emit and let the reducer merge.
- 2026-07-12: EventSource can't set headers, so the SSE token rides the URL; the default request logger serializes req.url and writes the secret to disk — redact `token=` in a req serializer (header tokens are safe).
- 2026-07-12: A concurrency-slot decrement must live in `finally`, not after the last await — otherwise one throw both leaks the slot forever and becomes an unhandledRejection (the run was launched with `void`).
- 2026-07-12: Trend deltas stay honest by storing daily snapshots as events and computing current − baseline; no history → no delta. Boot captures before the async scan finishes, so re-capture post-scan (unique id + last-write-per-day-wins in the reducer) to correct day one.
- 2026-07-12: A "lint" gate step that's an echo is worse than none — it reads green while checking nothing. Wire ESLint (flat config + typescript-eslint) scoped to the gaps tsc misses (unused vars, explicit-any); a clean codebase surfaces ~0 findings, so the cost is low and the honesty is high.
- 2026-07-12: Kill dead nav without faking features — route data-backed items to real bus-rendered pages and route not-yet-built items to one honest `/planned/:slug` placeholder; a `SectionHeader.actionTo` (Link) turns every "View all" into real navigation.
- 2026-07-12: A ⌘K command palette that indexes the live bus + pages is the honest replacement for a decorative search box, and it doubles as fast navigation across the whole app.
- 2026-07-12: Drop a superseded drizzle table with a NEW migration (DROP TABLE + journal entry) — never edit an applied migration's SQL; that breaks the hash check and existing DBs refuse to migrate.
- 2026-07-12: Latest-only signals (health/tokens/stats) persisted append-only grow the log forever even though the reducer keeps only the newest; a boot-time compaction that deletes all but max(seq) per key is state-preserving and keeps replay fast.
- 2026-07-12: `node --check` is the WRONG validator for Claude Code Workflow scripts — it rejects the top-level `return`/`await` those scripts rely on, because the harness runs the body inside an async function. Validate by compiling the source as an AsyncFunction body (with the injected globals as params) — it parses without executing and accepts exactly what the harness accepts.
- 2026-07-12: In a Workflow script a phase is assigned two ways — a `phase('X')` call OR `phase: 'X'` in an agent's opts (the opts form is the one to use inside pipeline/parallel stages, so concurrent stages don't race the global phase() state) — so a "declared vs used phases" check must count both forms or it false-flags the canonical pattern.
- 2026-07-12: CI should mirror the local gate exactly (`npm run verify`) — but a step that needs secrets or a browser (the Playwright `smoke`) stays a local/manual gate rather than being faked green in CI; an honest "skipped, and why" beats a hollow pass, same rule as the UI's no-fabrication.
- 2026-07-12: A bodyless `fetch` POST that still sends `content-type: application/json` makes Fastify 400 ("Body cannot be empty…"); send `{}` (or drop the header). React StrictMode double-invokes mount effects in dev, so the smoke's zero-console-error gate saw it twice — that gate earns its keep by catching client/server contract slips a green typecheck can't.
- 2026-07-12: For a "catalog" view of on-disk artifacts (the workflow recipes), have the server read + parse the REAL files (extract just the balanced `meta` literal, eval that in isolation) rather than hand-maintaining a parallel copy — the visual then can't drift, and an unparseable file is skipped, not guessed (no-fabrication for reference data too).
- 2026-07-12: A one-click "install" button from a web UI is safe ONLY when the local server derives the command from a first-party allow-list keyed by an id the client sends (never a command string), token-gated, minimal-env, timed-out. The clean guard is the event's own `source.kind`: only fire on non-runner builds (real CI/scan), never on the runner's own builds. Add a short debounce as a second belt.

Store the final task string on the automation (not just a prompt-id ref) so it's editable and the server needs no prompt-composition logic; keep source{kind,ref} only for display/traceability.

The demo had hidden this by seeding the display name into `build.repo`; making the demo honest (seed the id) exposed + fixed the real BuildQueue bug. Fixtures should mirror real event shapes or they mask bugs.
- 2026-07-12: Merging a child's stdout+stderr into one line stream by ending the merge when BOTH streams emit `end` HANGS on a missing binary — ENOENT fires `error` (and often no stream `end`), so the reader `for await`s forever and the run sticks at "running". End the merged stream on child `close` OR `error`. Found via self-review of the setup-install + ultrareview runners; extracted one `spawnMerged` helper + a regression test (missing binary must terminate, not hang).

Show output honestly rather than parsing findings whose format could shift across CLI versions.
- 2026-07-12: Adding a field is only visible end-to-end if the SEED that carries it actually re-lands. The demo uses stable ids + `bus.publish` `onConflictDoNothing`, so against a persisted db the old row wins and the new field never appears — even though the schema, emitter, and reducer are all correct. Debug by reading the raw SSE snapshot (is the field there at all?) before suspecting the web; the "compacted N rows" boot log tells you it's a file db, not `:memory:`. Fix: boot the fixture world fresh (demo → in-memory unless DB_PATH set; smoke forces DB_PATH=:memory:).
- 2026-07-12: `.claude/workflows` recipes are a Claude Code *session* construct (invoked via the Workflow tool) — there is no `claude workflow run` to execute them headlessly, so a dashboard spawning `claude -p` can only run a single agent, never the multi-agent fan-out. The one real headless multi-agent CLI is `claude ultrareview` (branch/PR review). Verify a capability from `--help` before building a feature on it; don't promise fan-out the tool can't deliver.
- 2026-07-12: Tests that build a real server must be hermetic — GitHubSync started at boot and, when a GITHUB_TOKEN is in the env (true in CI), fired a real fetch whose 401 rejection could land AFTER the test closed the server → an intermittent vitest "1 error" with all tests green. - 2026-07-12: An LLM classifier belongs behind a deterministic fallback, not in front of one. The Claude command parser calls the Messages API with a FORCED tool call (structured output validated by the shared zod Intent schema), but returns the sync heuristic parser's result on no-key / API error / timeout / schema-invalid output — the command box never breaks and `parsedBy` records which actually ran. Keep the model's job to classification only: command text goes in the user turn framed as data-to-classify (convention 11), and a repoId the model invents that isn't in the known set is dropped, never dispatched. A thin fetch adapter pinned to a fixed anthropic-version (convention 12) beat adding the SDK — one call, no build step, injectable FetchFn seam for tests. Model haiku-4-5: a 5-way classification is the canonical cheap/fast case (convention 5), configurable if fuzzier language ever needs opus.
- 2026-07-12: A piped-but-unread child stream deadlocks the child, not just yours. The runner spawned `claude -p` with stderr='pipe' but read only stdout (stream-json via readline) — once the child writes >~64KB to stderr (verbose/auth diagnostics) the OS pipe buffer fills, the child blocks on write, and the run hangs until the wall-clock timeout. If you consume only one stream, set the other to 'ignore' (or actively drain it); don't leave it piped. Same failure family as the spawnMerged hang, different stream. Can't merge stderr into a stdout you're parsing as JSONL — it'd corrupt the protocol.

- 2026-07-13: "Fix itself, never breaks" honestly = resilience + AI diagnosis + CONFIRMED fix — not unattended auto-edit. Auto-applying LLM code changes to a running app is the opposite of "never breaks", so the line is: degrade gracefully (ErrorBoundary + setErrorHandler + process hooks that log+report but don't exit), diagnose the root cause via the API, and make the actual fix one-click-with-a-repo-picker through the existing runner + cwd allow-list. The user still confirms; the app just did all the thinking. Say this explicitly to the user rather than silently building a safer thing than asked.
- 2026-07-13: The capture path for failures must itself be incapable of failing (or looping). IncidentReporter.report() is fully try/caught (reporting a crash can't cause another) and throttles by fingerprint to 1/min — a component throwing every render, or an uncaughtException storm, would otherwise flood the bus AND fire an opus call per occurrence. Diagnosis runs fire-and-forget with its own catch, so a failed diagnosis leaves the incident honestly 'open' instead of wedging. Same discipline as a logger: the thing that records errors is the one thing that must never throw.
- 2026-07-13: A new bus entity stays a leaf to dodge the reducer import cycle. incidents.ts imports ONLY zod (inlines its own isoTs) so state.ts can import Incident/IncidentRecord for BusState without a cycle — state.ts is the reducer leaf and events.ts already depends on it; anything state.ts imports at module-eval must not import back. Mirrors the existing ReducibleEvent structural-typing dodge. Forced tool_choice + thinking conflict on Opus 4.8, so the diagnoser omits thinking and uses strict:true (additionalProperties:false + all required) for reliable structured output.
- 2026-07-16: An agent must not loosen its own guardrails, even to fix a confirmed bug in them. - 2026-07-16: Secrets in saved templates are pointers, never values: credentialsNote says WHERE the ASC key lives; the agent on the machine uses what's already there, and the rendered task explicitly forbids echoing key material. A template store must never become a second secrets store.
- 2026-07-16: Enforce a per-entity switch at the one choke point every path funnels through, not at each caller. "Agent dispatch off" is checked inside Runner.dispatch (blockedReason, before the allow-list), so the command box, prompt library, automations, incident fixes, and review fixes all honor it with one line and one test — a per-caller approach would have missed the next caller added. - 2026-07-16: Credentials for spawned git must ride in env, never argv or the URL. Clone uses the clean https URL in argv and injects auth via GIT_CONFIG_* extraheader env vars — argv is visible in `ps`, and a token-in-URL persists into .git/config as origin. Also always set GIT_TERMINAL_PROMPT=0 on non-interactive git: a private repo without credentials then fails fast with a mappable error instead of hanging on a hidden username prompt. - 2026-07-16: Read the CONFIGURED git remote (`git config --get remote.origin.url`), not the RESOLVED one (`git remote get-url`), when you want the true origin — get-url applies machine-level url.insteadOf rewrites (mirrors/proxies), which is exactly how this container rewrote github.com to a local proxy and made a correct parser look broken in tests. Probe the primitive directly (one tsx -e script) before assuming the parser is at fault.
- 2026-07-16: Per-PID temp store files leak state BETWEEN buildServer instances in one test process — the second "fresh install" server read the first server's project dirs and really cloned a repo (through the git proxy) in a unit test. When a test needs a genuinely fresh store, delete the pid-keyed file first; when asserting a 4xx guard, make sure shared-file state can't satisfy the guard's precondition.
- 2026-07-16: The easy "open a PR" flow is a LINK, not an API write. New PR = GitHub's own compare page (`/compare/<branch>?expand=1`) prefilled; Open PR = the live PR's URL fetched read-only per branch. Zero forms to build, zero write scopes to hold, GitHub keeps the confirm step — the polished flow is also the safest one.
- 2026-07-16: An AI feature that can't run honestly must refuse, not degrade into fiction. The command parser and incident diagnoser have heuristic fallbacks because a heuristic can genuinely classify/pattern-match — but a heuristic cannot REVIEW code, so Auto-Review has none: no key → typed NoKeyError → manual runs 400 with "connect a key" and auto runs skip silently (no failed-row spam every poll). Pick the fallback per feature by asking "can the fallback do the real job?" — if not, the honest degraded state is refusal, and the UI says "nothing here is simulated".
- 2026-07-16: Ground LLM output against the input before storing it. The reviewer drops any finding whose file path doesn't literally appear in the diff (one `includes()` check) — a cheap, deterministic anti-hallucination guard that makes "the model named a file it never saw" structurally impossible downstream. Same family as "drop hallucinated repoIds not in the known set": validate model output against the ground truth you already hold, not just against a schema.
- 2026-07-16: Auto-triggers on user data need a consent baseline. Enabling auto-review seeds lastSha to the CURRENT head so only commits made AFTER opting in get reviewed — enabling a feature must never retroactively process old work the user didn't ask about. Same shape as the notifier dedup: the safe default is "from now on", not "everything ever".
- 2026-07-16: When a test of an honest-error path fails, check which side is wrong before "fixing" the code.
