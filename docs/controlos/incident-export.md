# Incident reports and browser-origin checks

Diagnostics offers an explicit Download report action for one incident. The authenticated endpoint `GET /api/incidents/:id/export` returns a versioned JSON report with generation time, incident identity/time, captured error text and its available diagnosis. Fields are projected explicitly; raw event payloads, profile files, credentials and arbitrary additional properties are excluded. Text is masked with current configured credentials before bounded truncation. Responses use `Cache-Control: no-store` and an attachment filename. Failed downloads show an error without producing a local or raw-data fallback. Reports can still contain project text and should be reviewed before sharing.

The export API regression exposed a separate boundary gap: a valid key with a hostile Origin still received a server response. The server now rejects supplied origins outside the configured web origin and explicitly served local web origins. This check runs before CORS preflight handling and independently of Host and credential validation. Missing Origin remains supported for local CLI/native callers, who still need normal authentication. Proxy headers do not grant a trusted origin. This is not private HTTPS, remote-device pairing or a trusted-proxy implementation.

A real child-process request-log regression also reproduced a connector credential leak: the request serializer masked the ControlOS access key but not a configured provider value placed in an ordinary URL parameter. It now masks current configured connection values too. The original red log `controlos-request-redaction-before.log` contains only the synthetic canary. Existing real-child provider-output tests continue to cover redaction before runner persistence and event publication.

The built-browser probe `node --import tsx scripts/probe-incident-export.mts` uses a synthetic incident through the production reporter, SSE, API and renderer. It checks masked DOM text, actual JSON downloads, no raw fallback after a network failure, zero runs and 1536/390-pixel layout. Source/build/report/screenshot hashes are recorded in `incident-export-evidence.json`. Unit/API coverage is in `incidents/export.test.ts`, `incidents/requestLogRedaction.test.ts` and `securityOrigin.test.ts`. T23 and T27 remain open for their complete acceptance scope.

The unrelated intermittent automation-history failure from the preceding change remains unresolved. Isolated observation completed 1,000 guarded history writes and 100 complete transaction/receipt/history cases without reproducing it. Logs `controlos-history-observe.log` and `controlos-history-transaction-observe.log` record the separate synthetic fixture roots. No production profile was modified and no file-identity protection was weakened.
