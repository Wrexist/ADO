# Historical execution and independent verification

The API no longer treats a stored `runs.verify_verdict` summary as sufficient evidence. A displayed verdict requires a verification-evidence row for the same run, head SHA, content digest and verdict. Without that binding, `verifyVerdict` is null: the shared contract's unknown/not independently verified value. Historical `done` remains execution success, and a historical human judgment remains historical data. Reading or migrating the profile does not create a task, approval or verification record.

The disk-backed migration regression constructs the actual schema through migration 0004, before durable execution and independent verification were introduced. It inserts three historical `done` runs with null, pass and fail summaries and historical accepted judgments. The production server then applies all current migrations and serves the authenticated list/detail APIs. Each run remains `done`/`succeeded` with exit code 0, but independent verification is unknown and evidence/approval histories are empty. A second production-server boot repeats these assertions. Direct SQLite comparison confirms the original status, verdict, human judgment and exit code were preserved, and no planning tasks were invented.

The regression failed before the fix because the legacy pass summary was returned as independently verified. Afterward it passed alongside real verification/approval and task-review API regressions (9 tests in 3 files).

Reproduce with `npx vitest run apps/server/src/runner/legacyVerification.test.ts apps/server/src/runner/approvalApi.test.ts apps/server/src/runner/taskReviewApi.test.ts`. Local logs are `controlos-legacy-verification-before.log` (expected failure) and `controlos-legacy-verification-focused.log` (pass). The test keeps its synthetic `controlos-legacy-verification-*` temporary profile for inspection. It never migrates the user's profile.

T37 is locally passed against this disk-backed migration and reopen scenario. [Version-bound evidence](legacy-verification-evidence.json) records source/migration hashes, command, environment and log hashes. The contract represents unknown verification as null, not a fabricated pass. This is source-runtime evidence on Windows/Node 22.18.0. It does not certify installer updates, migration interruption, a real user-profile restore or the complete R1 gate.
