# Reported usage and missing counters

The run-stats API retains reported input/output sums and returns the number of runs that supplied each counter, both for the whole window and each repository/model bucket. A reported zero counts as present. Null counters contribute nothing to the reported sum but do not become measured zero usage. `runsWithoutUsage` retains its existing meaning: neither counter was reported. Independent coverage counts also expose runs with only one counter. Coverage is derived at read time from existing rows; no migration or rewrite of historical counters occurs.

Analytics shows `Unknown` when no counter was reported, a reported subtotal with `partial` when coverage is incomplete, and the reported number when all relevant counters are present. It states input/output coverage explicitly. Repository/model bars compare reported subtotals only. Historical token snapshots lack coverage metadata and are labelled accordingly. Session-derived estimates remain separately labelled. Cost is explicitly unknown because the application has no verified pricing or billing data; no currency estimate or billed amount is invented.

The API regression `apps/server/src/runUsage.test.ts` seeds a separate on-disk profile with absent, explicit-zero, input-only and output-only usage. It checks whole-window and per-bucket coverage, excludes an old run outside the requested window, and reopens the profile to verify persistence. `apps/web/src/lib/usage.test.ts` checks the corresponding display distinctions.

`node --import tsx scripts/probe-usage.mts` builds the renderer and exercises the production API in a synthetic profile at 1536 and 390 pixels. It checks entirely unknown usage, mixed unknown/zero/partial usage, coverage, cost text, page errors and horizontal overflow. Screenshots use DEMO labels. Hash-bound artifacts are recorded in `usage-ui-evidence.json`. No actual provider, price-table staleness or billing acceptance is claimed; T33 remains open for the full scenario.
